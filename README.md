# 婚礼动态请柬

网页标题统一为“shishi x 之南 婚礼请柬”。2026-11-06 书房改为高清静态场景与实时风铃、火焰结合。加载页必须等待静态画面、点击遮罩、风铃、火焰、全部音乐和互动音效、骰子、3DS 视频及互动模型文件下载完成才结束。手机与电脑共用 3200×3200 背景和灯光，不再叠加手机专属加深阴影。

状态图在入场前解码完成；物品检视窗口也在入场前完成模型解析、动画边界计算、贴图上传和着色器预编译，并用同一个检视渲染器预绘制首帧。首次点击复用已准备的资源和渲染上下文；手机检视继续使用优化模型。拿走信物、打开笔记、打开盒子、取走信封和破坏锁具均同步切换桌面状态图。3DS 视频保持静音下载，只有调查游戏机才初始化播放器并播放，失败可以在互动窗口重试。

`node prepare-static-room.mjs` 从完整电脑模型重新渲染背景和状态图，不减少源模型面数；风铃仅压缩纹理和几何传输编码，保留几何拓扑。更改相机、物品摆放、材质或笔记文案后需要重新生成。背景文件在 `assets/static-room/`，运行入口是 `study-static-room.js`；`study-loft.js` 保留为离线渲染源。专项验证：`node check-static-room.mjs`、`node check-terminal-loading.mjs`、`node check-handheld-media.mjs`。

物品点击使用独立、关闭抗锯齿的 RGB 点击图，颜色与物品 ID 固定对应；未知颜色不会被解释成其他物品。`picking-v2.json` 同时绑定带内容哈希的基础点击图和拿走信物、翻开笔记、打开盒盖的区域补丁，避免混用不同版本的图和 ID。吊坠链条内部保留可点击范围。完整背景重建会自动调用 `prepare-static-picking.mjs`；只修点击区域可单独运行此工具。`node check-static-picking.mjs` 以原始三维几何射线取得的独立验证点，检查全部物品、吊坠边缘、物品状态变化及手机缩放拖动。

2026-11-05 确定淡奶油米色版为最终稿，GitHub `main` 以此版本继续维护。加载页保留扫描纹和移动扫描光带；互动背景透明度为 30%，模糊为 7.2px。手机书房全屏显示场景，桌面光影统一使用电脑场景效果。

仓库仅保留两条使用路径及其实际运行资源：

- `index.html`：欢迎首页 → 高清静态书房与局部动态 → 三维物品调查、检定、寻找并阅读婚礼请柬。
- `invitation.html`：首页直接阅读 → 拆信封与展信动画 → 完整请柬。

骰子是首页内部组件，检定卡片在加载页期间提前布局，背景与信物缩略图解码、骰子首帧绘制完成后才允许进入房间；预热不执行掷骰。保留书房检定，不再提供独立骰子页面。蒲公英动画位于请柬末尾，背景从雾蓝渐变为深灰蓝，不提供独立蒲公英页面。

手机从首页或书房跳过游戏阅读时，全屏阅读窗口保留原有音乐播放器，让点击直接触发播放；请柬中的按钮控制同一音乐通道，并支持浏览器返回。直接访问 `invitation.html` 仍可独立阅读。竖屏可双指捏合缩小到整个桌面，杯子和笔记本完整可见，上下由同一场景渲染的天花板和地板填满，放大后可左右拖动；能直接展示完整场景的桌面横屏和手机横屏关闭缩放，旋转屏幕后自动切换。

3DS 互动时，上屏自动单次播放 `assets/handheld-memory.mp4`，下屏显示 `assets/handheld-logo.webp`。普通视角可旋转；“拿起仔细看”放大并锁定视角，“放在桌上”恢复旋转，均不重播视频。关闭互动后，只恢复进入前正在播放的音乐。

2026-11-06 采用偏重画质的 3DS 媒体压缩版本：视频从 3.77 MB 降至 3.02 MB，保留 660×494、30 fps、完整时长和未经重新编码的原始 AAC 音轨；下屏图从 768×768、173 KB 调整为实际绘制所需的 480×480、63 KB。两项合计减少约 0.86 MB，加载和播放方式保持原有设置。

手机端保存按钮在页面内展示完整 JPG 长图，用户长按图片后通过微信/系统菜单保存到相册，不再触发文件下载或跳转浏览器。相册版本为 `assets/wedding-invitation-album.jpg`（1080×8238），仅在点击保存时加载；电脑端保留原始高清 JPEG 下载。

## 本地运行

安装 Node.js 22 或更新版本，然后双击「启动书房预览.cmd」，或运行：

```powershell
node build-browser.mjs
node preview.mjs --open
```

打开 http://127.0.0.1:4175/。三维页面通过 HTTP 加载，不能直接双击 HTML 文件。

## 文件范围

保留手机与电脑当前使用的模型、图片、音乐、音效和第三方代码许可证。

`模型库/` 和 `output/loft-viewer/` 只跟踪页面实际使用的运行资源。完整模型库、Blender 源文件、历史版本、压缩包、制作预览、测试截图和本地备份不上传。请保留仓库中的运行模型，否则书房会缺少物品或房间。

`github-files.mjs` 根据两个入口页面和当前手机、电脑资源配置生成上传白名单。`.gitignore` 使用白名单，避免把完整模型库再次提交。新增页面依赖后运行：

```powershell
node github-files.mjs --write-ignore
```

然后在 Git 客户端检查并提交新增文件。若增加维护工具，将其加入 `github-files.mjs` 的工具清单。

## 修改与检查

- 婚礼信息与歌单：`data.js`。
- 书房文案和规则：`study.js`、`study-rules.js`；修改后运行 `node build-browser.mjs`。
- 请柬长图、下载原图和音效：`assets/`。
- 蒲公英动画：`launch.js`、`launch.css`。
- 资源依赖：`node audit-runtime.mjs`。
- 检定与流程：`node check-study.mjs`、`node check-study-loft.mjs`。

运行 `npm test` 可构建并检查依赖、规则和交互流程。浏览器测试工具与截图留在本地。

## 部署

可将仓库根目录作为静态网站发布目录。保留资源路径和目录层级，尤其是 `output/loft-viewer/` 和 `模型库/` 中的运行文件。网页不需要 Node.js 后端。

也可运行 `npm run release`，生成独立发布目录 `output/site-release/`。发布目录和预压缩副本留在本地，不重复提交 GitHub。

第三方代码及许可证见 `vendor/`。

GitHub Pages 发布更新时，同步更新 `index.html`、`study-bootstrap.js` 和 `study-static-room.js` 的资源版本号。`static-room-downloads.js` 将模块版本传递给清单、房间图、扩展底图及状态图片，避免旧缓存与新脚本混用。
