2026-11-07 媒体兼容修复：风铃与其他短音效共用提前解码的 Web Audio 通道，连续摇动替换上一段铃声；唱片切歌在原点击事件中重新载入音源并调用播放。`audio-compat.js` 根据浏览器 Ogg Vorbis 播放能力选择原 Ogg 或 `assets/audio-compat/` 下的 MP3，覆盖歌单、风铃、骰子、八音盒和其他音效，不修改原音频文件。MP3 资源纳入运行依赖审计及发布清单；更新 Ogg 后可在具备本地 FFmpeg 的环境运行 `npm run prepare:audio-compat`。预览服务支持音频字节范围请求。

其余音效复查：骰子改为共用提前解码的 Web Audio 通道；手势恢复同时处理 `suspended` 和 iOS 的 `interrupted` 状态。若恢复请求被拒绝、仍未运行或超过 1.5 秒无响应，短音效返回失败，不把无声节点报告为已播放，也不阻塞连续翻书流程。浏览器自行暂停的篝火、唱片、八音盒，以及 3DS 关闭后恢复八音盒被拦截的情况，会在下一次有效点击时重试；用户主动暂停或离开房间不会自动重播。手机内嵌请柬复用父页面已解锁的音效上下文，加载终端也支持中断后的点击恢复。

3DS 播放期间把视频元素放入互动弹窗内，避免留在弹窗后方；原有 30 fps 纹理刷新保留。若播放被拒绝、浏览器自行暂停，或播放请求超过 2.5 秒仍未推进，显示“点击播放视频”恢复入口。`npm run test:media` 验证原 Ogg 与兼容 MP3 播放、歌单切换、视频预初始化、无元数据模拟、播放被拒绝/挂起及暂停后的恢复；这些自动化检查不能替代 iPhone 真机验证。

进入书房前的 3DS 预加载不调用 `play()`，并显式关闭 autoplay，保持 `defaultMuted`、`muted` 和暂停。视频声音只允许在书房就绪、3DS 互动窗口可见且本次播放已获明确请求时开启；延迟下载完成和 `WeixinJSBridgeReady` 都不授权播放。加载页、切后台、页面缓存返回、关闭互动后的意外播放或取消静音事件会重新静音并暂停；返回可见页面后由“点击播放视频”恢复。iPhone 可能忽略脚本音量，因此静音保护不依赖 `volume=0`。页面真正离开时不恢复其他媒体。`npm run test:ios-video` 覆盖这些流程及误触发互动回调；Safari/微信配置使用 Chromium 模拟权限和媒体事件，报告位于 `output/handheld-ios-audit/report.json`，不代表已进行原生 iPhone 测试。

## 本地运行

安装 Node.js 22 或更新版本，然后双击「启动书房预览.cmd」，或运行：

```powershell
node build-browser.mjs
node preview.mjs --open
```

打开 http://127.0.0.1:4175/。三维页面通过 HTTP 加载，不能直接双击 HTML 文件。

## 文件范围

保留手机与电脑当前使用的模型、图片、音乐、音效和第三方代码许可证。

`模型库/` 和 `output/loft-viewer/` 只跟踪页面实际使用的运行资源。完整模型库、Blender 源文件、历史版本、压缩包、制作预览、测试截图和本地备份不上传。请保留仓库中的运行模型，否则书房会缺少物品或房间。

`github-files.mjs` 根据两个入口页面和当前手机、电脑资源配置生成上传白名单。`.gitignore` 使用白名单，避免把完整模型库再次提交。新增页面依赖后运行：

```powershell
node github-files.mjs --write-ignore
```

然后在 Git 客户端检查并提交新增文件。若增加维护工具，将其加入 `github-files.mjs` 的工具清单。

## 修改与检查

- 婚礼信息与歌单：`data.js`。
- 书房文案和规则：`study.js`、`study-rules.js`；修改后运行 `node build-browser.mjs`。
- 请柬长图、下载原图和音效：`assets/`。
- 蒲公英动画：`launch.js`、`launch.css`。
- 资源依赖：`node audit-runtime.mjs`。
- 检定与流程：`node check-study.mjs`、`node check-study-loft.mjs`。

运行 `npm test` 可构建并检查依赖、规则和交互流程。浏览器测试工具与截图留在本地。

## 部署

可将仓库根目录作为静态网站发布目录。保留资源路径和目录层级，尤其是 `output/loft-viewer/` 和 `模型库/` 中的运行文件。网页不需要 Node.js 后端。

也可运行 `npm run release`，生成独立发布目录 `output/site-release/`。发布目录和预压缩副本留在本地，不重复提交 GitHub。

第三方代码及许可证见 `vendor/`。

GitHub Pages 发布更新时，同步更新 `index.html`、`study-bootstrap.js` 和 `study-static-room.js` 的资源版本号。`static-room-downloads.js` 将模块版本传递给清单、房间图、扩展底图及状态图片，避免旧缓存与新脚本混用。
