# 旧印 · 无人书房

固定镜头的图层式调查游戏。`index.html` 初次打开显示婚礼欢迎页，姓名与昵称分列对应，提供“参观书房，寻找请柬”和直接阅读请柬两个入口。进入书房后选择一件随身物品，选定后提示属性 +10，再开始调查。书房及弹窗不再提供跳过入口；物品详情只显示标题、加大的描述及操作按钮，“返回”关闭详情。书房统一使用本地字体：英文 Blackletter 与厚重尖角中文，操作按钮沿用首页磨损渐变材质。拆开信封后可以进入 `invitation.html`。

## 本地预览

网页依赖全部在项目内，不需要安装包。直接双击 `index.html` 可以进入、选择物品、探索和阅读请柬，也能显示原有 3D 双骰动画。通过 HTTP 预览访问：

```powershell
npm run dev
```

浏览器打开 http://127.0.0.1:4175 。`npm run dev` 会先生成兼容本地文件的 `study-browser.js`，再启动服务。直接修改源文件后，也可以单独运行 `npm run build` 重新生成。

## 场景与特写

- 主场景使用认可参考方向的高清绘制底图，没有加载基础几何体拼装的 3D 书房。
- 笔记、唱片机和抽屉有独立的细轮廓和点击区域。牛来和合照相框也有高亮轮廓，可点击查看赠礼描述和合照调查页。
- 交互时，物品在屏幕中央展示独立高清特写，下方显示描述与选项。
- 已制作笔记、唱片机、关闭的抽屉、打开的抽屉、信封、指虎匕首和钥匙的特写。抽屉打开后，主场景同步切换局部图层；唱片播放时有轻微旋转光泽反馈。
- `assets/elder-sign.png` 是用户提供的原始符号。当前 v4 场景已将原始旧印与磨损遮罩固化到笔记封面，PNG、WebP 与网页显示一致，不再依赖网页额外叠加封面旧印。物品特写与火漆仍叠加同一原图。`export-sealed-scenes.mjs` 可重新导出当前底图；它渲染原有 SVG 图层，不重新生成符号。
- 九张网页用 WebP 共约 2.3 MB。场景底图约 188 KB；特写在需要时加载。PNG 原图和原始参考仍保留。
- 生成方式和素材提示词见 `assets/art-direction.md`。

`study-art.js` 负责图层显示，`study.js` 负责互动，`study-rules.js` 负责检定。未来可替换场景渲染器，沿用 `study-state` / `study-object` 事件和游戏规则。旧的 `study-scene.js` 真实 3D 原型仍保留，但当前入口不加载它。

## 探索规则

- 力量、智力、意志初始各 55；镇纸、钢笔、旧吊坠分别对其中一项加 10，属性卡不展示给玩家。
- 笔记进行一次智力检定。所有结果都获得钥匙；成功会解读出唱片机暗格的开启方式。
- 唱片机在笔记成功后可直接开暗格；其余情况下可进行力量检定。所有结果都取得匕首。
- 有钥匙可打开抽屉；无钥匙可尝试一次力量极难检定，门槛为力量五分之一。失败后仍可找到钥匙开锁。
- 信封获得后可从物品栏检查。触碰旧印执行一次意志检定，返回后不会重复。所有结果都能拆信。
- 有匕首可小心拆信；没有匕首可撕开，或返回寻找工具。拆开后才出现新人姓名、请柬和阅读入口。
- D100 的 1 是大成功；属性至少 50 时 100 是大失败，属性低于 50 时 96–100 是大失败。
- 检定时自动弹出中央小窗口，双 d10 沿用 `dice.html` / `dice.js` 的真实 3D 骰子，数值随机。投掷结束后显示点数及成败 3 秒，再自动关闭并应用结果，无需再次点击。书房本身无需 WebGL，骰子失去 3D 渲染时仍可以数值方式完成检定。

## 声音

默认不自动播放。`data.js` 中：

- `studyMusic`：书房低沉环境声，当前为原创合成的 `assets/study-drone.wav`。
- `recordMusic`：唱片机的小调音乐，当前为原创合成的 `assets/record-nocturne.wav`。
- `music`：正式请柬与独立蒲公英页面的音乐，和书房分开配置。

唱片开始时暂停正在播放的背景音乐；停止或自然播放结束时，只恢复原本已在播放的背景音乐，保留进度。主动关闭背景音乐会取消恢复。之前的试用音轨也保留在 `assets/`。

## 蒲公英完整保留

`dandelion.html` 从修改前的原始入口恢复，继续引用原有 `launch.js`、`launch.css`、`garden-dusk.png`、`data.js` 和 `music.js`。蒲公英脚本、样式与花园素材没有删除或覆盖。可以单独打开这个页面，支持轻触、跳过与重播，也可复制其开场部分到其他页面。它不插入当前书房流程。

## 部署

本地版本尚未发布到公网。上传到原有 NAS 或静态托管目录时保留以下文件：

- `index.html`、`study.css`、`study-browser.js`（运行 `npm run build` 生成；源文件 `study.js`、`study-rules.js`、`study-art.js` 建议一起保留）
- `invitation.html`、`style.css`、`launch.css`、`data.js`、`music.js`、`botanical.svg`
- `assets/*.webp`、`assets/elder-sign.png` 和使用到的音频
- `dice.html`、`dice.css`、`dice.js`、三张 `dice-*-reference.png` 与整个 `vendor/`
- 独立蒲公英页面另需 `dandelion.html`、`launch.js`、`garden-dusk.png`
- `data.js` 引用的照片或其他音频

主链接仍指向 `index.html`。婚礼信息仍在 `data.js` 中修改；到场时间、具体地址等应在正式分享前确认。请在真实手机和微信内置浏览器中复查音频权限与显示效果。

## 验证

```powershell
npm test
node check-browser.mjs
```

规则检查涵盖三种开场加值、600 次检定判断、笔记与抽屉分支和音乐恢复。浏览器检查覆盖桌面、320/390/430 像素手机、平板、各物品特写、完整分支、提前剧透检查、无 WebGL、音乐切换、蒲公英跳过/重播，以及直接通过 file:// 打开时从开始到请柬的完整流程。

`check-browser.mjs` 使用开发机自带的 Playwright 与 Chrome；其他机器需调整脚本中的模块和浏览器路径。网页本身不依赖它们。测试截图在忽略的 `output/` 文件夹。

当前书桌物品的互动近景已统一为依照桌面样式重绘的 Source 风格：相框、笔记本、唱片机、牛来，以及抽屉关闭/有信封/空抽屉三个状态。均使用独立近景素材完整显示物品，牛来和空抽屉不再裁切放大场景底图。
